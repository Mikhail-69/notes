# Топ вопросов по Сетям

## Чем TCP и UDP отличаются друг от друга?

Оба протокола работают на транспортном уровне и оба решают одну и ту же задачу: доставить данные от процесса к процессу, но они используют разных подход.

TCP c установлением соединения - SYN, SYN-ACK, ACK; и только после этого начинается передача. Гарантирует доставку, порядок и целостность.

В UDP нет ничего этого, зато нет ожижания подтверждений, простой и задержек.

## Как происходит TLS рукопожатие? 

> SSl когда-то переименовали в TLS

3 шага SSL:
    - Клиент шлет ClientHello (сообщает список шифрования который он поддерживает). Сервер отвечает своим ServerHello, где отвечает каким из предложенных алгоритмов они будут пользоваться
    - Сервер отправляет сертификат с публичным ключом для подтверждении себя.
    - Клиент берет секрет (число), шифрует его публичным ключом сервера, который получил из сертификата, и отправляет. Сервер получает письмо, расшифровывает приватным ключом, из этого числа обе стороны высчитывают одинаковый ключ шифрования и всё общение шифруется дальше.

Шаги TLS:
    - Тот же Client Hello + SNI (имя сервера)
    - Тот же Server Hello
    - Проверка сертификата сервера и обмен ключами.
    - Клиент создает pre-master secret и отправялет его в ответ серверу
    - Генерация сессионого ключа. Сейчас есть 3 разных числа (Client random, server random, pre-master secret) и из них вычисляется симметричный ключ.
    - Обе стороны отправляют друг другу зашифрованное сообщение Finished. Если обе стороны смогли расшифровать, то все хорошо.

## Что такое mTLS?

Это взаимная аутентификация. Не только клиент проверяет сертификат сервера, но и сервер проверяет сертификат клиента.

## Назовите все уровни OSI

1. Физический. Оптика, биты, вольты, кабели, радиоволны. Задача передать единицы и нули
2. Канальный. MAC-адреса, кадры, коммутаторы, vlan. Задача доставка кадра внутри одного сегмента сети.
3. Сетевой. IP-адреса, пакеты, маршрутизация, IP, ICMP (PING), ARP. Задача доставка пакета между разными сетями.
4. Транспортный. Порты, сегменты, TCP, UDP. Доставка данных конкретному процессу на сервере.
5. Сеансовый. RPC, GRPC. Управление сессиями.
6. Представления. JPEG, ASCLL, TLS. Кодировки, форматы данных, шифрование.
7. Прикладной. HTTP, DNS, SMTP, SHH. Работа с приложениями. 

## Как диагностировать доступность порта и сервиса?

Разделим на 2 части: сервер и клиент. 
Сервер:
1. Сервис вообще запущен? Команда `ss-tulpn` покажет все порты которые слушаются и процессы которые их занимают.
2. Файрвол не мешает? Команды `iptables -L -n -v` и `ufw status`. Проверить что правила файрвола не дропают пакеты.
3. Security groups. Это файрвол на уровне облака.

Клиент:
1. Доступность снаружи. Ping, Telnet IP порт. Должны быть Connected, а не trying. Может быть еще ошибка connection refused.
2. NC-VZ IP порт.
3. Curl -v https://ip:порт  Тут посмотрит DNS-резолвинг, TCP-соединения, TLS-рукопожатия, http-ответ

Если проблема где-то между, то обращаемся к traceroute

## Какие бывают http-статус-коды?

5 классов. 100,200,300 - не интересны, с ними все понятно, а вот 400 (bad request), 401 (unauthorized), 403 (forbidden), 404 (not found), 429 (too many requests), 500 (internal server error), 502 (bad gateway), 503 (service unavailable), 504 (gateway timeout).

## Что происходит когда вы вводите адрес в браузере?

1. DNS Lookup.
   - Смотрит кэш браузера. Если нет - идем дальше.
   - Смотрим кэш системы. Если нет - идем дальше.
   - Смотрим файл /etc/hosts. Если нет - идем дальше.
   - Смотрим DNS-сервер провайдера. Если нет - дальше.
   - Смотрим Корневой сервер. От туда в сервер Зоны.com. От туда к авторитетному серверу гугла.
   - Получаем IP и кэшируем его.
2. TCP Handshake.
   - Установка трехступенчатого рукопожатия SYN, SYN-ACK, ACK
3. TLS Handshale
   - Мы открыли http, поэтому сверху запускается TLS (client и server hello, SNI, Сертификаты, Обмен ключами и генерация сессисионного ключа)
4. HTTP Request.
5. Обработка запроса на сервере. Тут уже зависит от архитектуры сервера и того как оно в итоге сгенерирует html и вернет ответ. Запрос может:
   - Попадет напрямую
   - Через балансировщик нагрузки
6. HTTP Response.
   - Нам вернули ответ 200 с html страничкой
7. Рендеринг. Браузер делает параллельные http запросы для css, js
