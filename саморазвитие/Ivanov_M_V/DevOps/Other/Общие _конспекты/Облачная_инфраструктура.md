# Облачная инфраструктура

### 1. Bare Metal (Своё железо)

**Мы отвечаем за всё.**

Железо в собственном дата-центре или арендованное физически. Полный контроль, но и полная ответственность.

---

### 2. IaaS (Infrastructure as a Service)
**Провайдер берёт на себя:**
- Физическое железо
- Виртуализацию

**Нам достаётся:**
- Виртуальные машины
- Сеть
- Диски (блочные хранилища)

**Примеры:** AWS EC2, Google Compute Engine, Yandex Compute Cloud, VK Cloud.

---

### 3. PaaS (Platform as a Service)
**Провайдер обеспечивает:** 
- Железо
- Виртуализацию
- Операционную систему 
- Runtime (среду выполнения)

**Нам достаётся:**
- Код приложения
- Его конфигурация

**Примеры:** Heroku, Google App Engine, Yandex Cloud Managed Kubernetes.

---

### 4. FaaS / Serverless (Function as a Service)

**Мы отдаём провайдеру:** куски кода (функции).

**Провайдер запускает их только при наступлении события:**
- HTTP-запрос
- Сообщение в очереди
- Загрузка файла
- Изменение в базе данных

**Особенности:**
- Серверы запускаются только когда это требуется
- Платим меньше денег
- Теряем почти весь контроль
- Сильнее привязываемся к провайдеру

**Примеры:** AWS Lambda, Google Cloud Functions, Yandex Cloud Functions.

---

### 5. SaaS (Software as a Service)

**Провайдер держит весь стек целиком.**

Мы просто пользуемся готовым продуктом через API или браузер.

**Примеры:** Google Workspace, Microsoft 365, Notion, Figma.

## Модели развертывания (Deployment Models)

Где физически находится облако?

| Модель | Описание | Плюсы | Минусы |
|--------|----------|-------|--------|
| **Публичное облако** | Общий провайдер, общее железо | Дешево, быстро, готовые сервисы | Железо не наше, сосед по серверу неизвестен |
| **Приватное облако** | Самообслуживание, API, железо принадлежит одной организации | Полный контроль, безопасность | Дорого, требует команду специалистов |
| **Гибридное** | Чувствительное и стабильное — у себя, пики нагрузки и эксперименты — в публичном облаке | Баланс контроля и гибкости | Сложность управления, интеграция |

## Как это работает?

### 1. Виртуализация
**Гипервизор** — прослойка, которая режет один физический сервер на множество виртуальных машин.

### 2. Контейнеризация
Контейнеры изолируют отдельные процессы поверх одной ОС (Docker, containerd).

### 3. VPC (Virtual Private Cloud)
Виртуальная сеть внутри облака. Нам выдают изолированную виртуальную сеть, работающую поверх физической сети провайдера.

### 4. Хранилище
| Тип | Описание | Пример |
|-----|----------|--------|
| **Блочное** | Диски для ВМ (как обычный HDD/SSD) | EBS, Yandex Disk |
| **Объектное** | Хранилище для файлов/бэкапов (ключ-значение) | S3, Yandex Object Storage |
| **Файловое** | Сетевые файловые системы (NFS) | EFS, Yandex FNS |

### 5. Отказоустойчивость
Расположение сервиса на нескольких серверах в разных зонах доступности (Availability Zones) и даже регионах.

## Плюсы и минусы облаков

### ✅ Плюсы

| Преимущество | Пояснение |
|--------------|-----------|
| **Оплата по факту** | Затраты идут по мере использования |
| **Скорость развертывания** | Минуты вместо недель |
| **Эластичность** | Оплата за реальную нагрузку |
| **Managed-сервисы** | Снимают нагрузку с команды → команда занимается продуктом, а не обслуживанием БД |
| **Глобальность** | Легко масштабироваться по всему миру |

### ❌ Минусы

| Недостаток | Пояснение |
|------------|-----------|
| **Привязка к вендору (Vendor Lock-in)** | Чем глубже мы залезли в проприетарные сервисы — тем дороже уходить |
| **Цена на масштабе** | При высокой и стабильной нагрузке иногда дешевле иметь свои сервера |
| **Egress-трафик** | Загружать данные в облако бесплатно, а выгружать наружу — платно и дорого |

## Когда что подходит?

| Сценарий | Рекомендация |
|----------|--------------|
| **Стартапы** | ☁️ Облако — быстро, дёшево на старте |
| **Разработка и тесты** | ☁️ Облако — можно быстро создавать и удалять окружения |
| **Непредсказуемая нагрузка** | ☁️ Облако — эластичность |
| **Долгая дистанция** | 🖥️ Своё железо — дешевле при стабильной нагрузке |
| **Огромные стабильные загрузки** | 🖥️ Своё железо |
| **Жёсткие требования (закон, безопасность)** | 🖥️ Своё железо — данные на своей территории |

## 🧠 Итог

> Облако — это **инструмент**, а не серебряная пуля. Выбор между облаком и своим железом — это всегда компромисс между **скоростью/гибкостью** и **контролем/ценой на масштабе**.

**Архитектор облачной инфраструктуры** должен уметь выбирать правильную модель для каждой конкретной задачи.
