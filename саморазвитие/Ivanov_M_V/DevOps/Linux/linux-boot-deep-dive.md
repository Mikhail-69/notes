## Режим реальных адресов

При включении CPU стартует в **реальном режиме** (16-бит).

**Сегментация:** физический адрес = `сегмент * 16 + смещение`.

Максимум: `0xFFFF * 16 + 0xFFFF = 0x10FFEF` (1 МБ + 64 КБ − 16 байт).  
С отключённой линией A20 адрес «заворачивается» в `0x00FFEF`.

**Карта памяти в реальном режиме:**

| Диапазон | Назначение |
|----------|------------|
| `0x00000000 – 0x000003FF` | Таблица векторов прерываний |
| `0x00000400 – 0x000004FF` | Данные BIOS |
| `0x00007C00 – 0x00007DFF` | Загрузчик (512 байт) |
| `0x000A0000 – 0x000BFFFF` | Видеопамять (VRAM) |
| `0x000F0000 – 0x000FFFFF` | Системная BIOS |

> Первая инструкция CPU — `jmp` по адресу `0xFFFFFFF0` (вектор сброса), которая ведёт в BIOS ROM.

## Вектор сброса и BIOS

CPU серии 80386+ после сброса:

| Регистр | Значение |
|---------|----------|
| `IP` | `0xfff0` |
| `CS selector` | `0xf000` |
| `CS base` | `0xffff0000` |

**Начальный адрес:** `0xffff0000 + 0xfff0 = 0xfffffff0` (16 байт ниже 4 ГБ).

Там лежит инструкция `jmp` на точку входа в BIOS.

**Что делает BIOS:**
- POST (проверка железа).
- Инициализация устройств.
- Поиск загрузочного устройства (по порядку из настроек).
- Загрузка первых 512 байт (MBR) в память по адресу `0x7C00`.
- Проверка сигнатуры `0x55AA` в конце сектора.
- Передача управления загрузчику.

## Загрузчик (GRUB2)

**Цепочка GRUB2:**

boot.img (512 байт, MBR)
↓
diskboot.img (в неиспользуемой области)
↓
grub_main (C-код)
↓
grub_normal_execute → меню выбора ОС
↓
grub_menu_execute_entry → команда boot


**Что делает GRUB при загрузке Linux:**
- Загружает `vmlinuz` (сжатое ядро) и `initrd/initramfs` в память.
- Заполняет `setup_header` (заголовок ядра) значениями из командной строки.
- Передаёт управление по адресу `_start` (смещение `0x200` от начала `vmlinuz`).

**Протокол загрузки Linux** (`Documentation/x86/boot.txt`) описывает:
- Поля заголовка, которые загрузчик обязан заполнить.
- Требования к карте памяти.
- Хуки для «враждебных» сред.

## Код настройки ядра

Файл `arch/x86/boot/header.S`, метка `_start`.

**Что делает код настройки:**

1. **Выравнивает сегментные регистры** — `ds`, `es`, `ss` должны указывать на один адрес.
2. **Настраивает стек** — проверяет `ss`, при необходимости создаёт корректный стек.
3. **Обнуляет BSS** — секция неинициализированных данных.
4. **Проверяет магическое число** `0x5a5aaa55`.
5. **Переходит к C-коду** — вызывает `main()` из `arch/x86/boot/main.c`.

**Что делает `main()`:**

| Функция | Задача |
|---------|--------|
| `copy_boot_params` | Копирует `setup_header` в `boot_params` |
| `console_init` | Инициализирует `earlyprintk` (последовательный порт) |
| `init_heap` | Настраивает кучу для кода настройки |
| `validate_cpu` | Проверяет уровень CPU, long mode, SSE |
| `detect_memory` | Определяет карту памяти (E820, E801, 88h) |
| `keyboard_init` | Инициализирует клавиатуру |
| `query_ist`, `query_apm_bios`, `query_edd` | Запрашивает информацию у BIOS |

**Определение памяти через E820:**

```c
ireg.ax  = 0xe820;   // номер функции
ireg.cx  = sizeof buf;
ireg.edx = SMAP;     // магическое число
ireg.di  = (size_t)&buf;
```

BIOS возвращает записи вида: **[начало, размер, тип].**

Пример вывода `dmesg`:
[    0.000000] BIOS-e820: [mem 0x0000000000000000-0x000000000009fbff] usable
[    0.000000] BIOS-e820: [mem 0x000000000009fc00-0x000000000009ffff] reserved

## Защищённый режим

**Зачем:** доступ к 4 ГБ памяти (вместо 1 МБ), поддержка страничной организации, уровни привилегий (ring 0–3).

**Управление памятью в защищённом режиме:**

- **Сегментация** — через GDT (Global Descriptor Table).
- **Страничная организация** — через таблицы страниц (появляется в long mode).

**Дескриптор сегмента (64 бита):**

```text
 63        56 55 54 53 52 51    48 47 46 45 44 43    40 39        32
+-----------+--+--+--+--+--------+--+--+--+--+--------+-------------+
| Base 31:24|G |D |L |AVL|Limit19:16|P |DPL|S |Type |Base 23:16 |
+-----------+--+--+--+--+--------+--+--+--+--+--------+-------------+
 31                    16 15                    0
+-----------------------+-----------------------+
|     Base 15:0         |       Limit 15:0      |
+-----------------------+-----------------------+
```

**Селектор сегмента (16 бит):**

```text
 15              3 2  1     0
+----------------+--+-------+
|     Index      |TI|  RPL  |
+----------------+--+-------+
```

**Переход в защищённый режим:**

1. Отключить прерывания (`cli`).
2. Загрузить GDT (`lgdt`).
3. Установить бит `PE` в `CR0`.
4. Выполнить дальний переход (`lret`) на 32-битный код.

## Long mode и таблицы страниц

**Long mode** — нативный 64-битный режим x86_64.

**Что даёт:**

- Регистры `r8`–`r15`, 64-битные `RIP`, операнды и адреса.
- RIP-относительная адресация.
- Два подрежима: 64-битный и режим совместимости.

**Условия для входа в long mode:**

1. Включить PAE (`CR4.PAE = 1`).
2. Создать таблицы страниц, загрузить `CR3`.
3. Включить `EFER.LME`.
4. Включить страничную организацию (`CR0.PG = 1`).

**Таблицы страниц, которые строит ядро:**

| Таблица | Размер | Записей |
|---------|--------|---------|
| **PML4** | 4 КБ | 1 |
| **PDP** | 4 КБ | 4 |
| **PD** (×4) | 4 КБ каждая | 2048 всего |

Итого: **2048 страниц по 2 МБ = 4 ГБ**.

**Загрузка CR3 и включение long mode:**

```assembly
leal pgtable(%ebx), %eax
movl %eax, %cr3          ; загрузить адрес PML4

movl $MSR_EFER, %ecx
rdmsr
btsl $_EFER_LME, %eax    ; установить бит LME
wrmsr

pushl $__KERNEL_CS       ; сегмент кода
leal startup_64(%ebp), %eax
pushl %eax
movl $(X86_CR0_PG | X86_CR0_PE), %eax
movl %eax, %cr0           ; включить paging и protection
lret                      ; дальний переход в 64-битный режим
```

## Декомпрессия ядра

После входа в long mode выполняется `extract_kernel` из `misc.c`.

**Шаги:**

1. Инициализация видео и консоли (повторно).
2. Настройка указателей кучи:
   `free_mem_ptr = heap; free_mem_end_ptr = heap + BOOT_HEAP_SIZE`.
3. **KASLR** (опционально): выбор случайного адреса.
4. Проверка выравнивания и границ адреса.
5. Вывод `Decompressing Linux...`.
6. Вызов `__decompress` (gzip / bzip2 / xz / lz4 / lzo).
7. `parse_elf` — перемещение ELF-сегментов в правильные адреса.
8. `handle_relocations` — релокация (если `CONFIG_X86_NEED_RELOCS`).
9. Возврат в `head_64.S` и `jmp *%rax` на распакованное ядро.

## KASLR — рандомизация адреса загрузки

**KASLR** (Kernel Address Space Layout Randomization) — защита от эксплуатации уязвимостей за счёт случайного размещения ядра в памяти.

**Управление:** параметр `nokaslr` в командной строке отключает KASLR.

**Что делает:**

1. Инициализирует таблицы страниц 1:1 (`initialize_identity_maps`).
2. Собирает зарезервированные области памяти (`mem_avoid_init`):
   - Текущая область декомпрессии.
   - `initrd`.
   - Командная строка ядра.
   - `boot_params`.
   - Регионы `e820`.
3. Выбирает случайный физический адрес (`find_random_phys_addr`):
   - Через EFI или e820.
   - Минимум — 512 МБ.
4. Создаёт страницы 1:1 для выбранного адреса.
5. Выбирает случайный виртуальный адрес (`find_random_virt_addr`) — только для x86_64.
6. Возвращает адреса в `output` и `virt_addr`.

**Источники случайности** (`kaslr_get_random_long`):

- `RDRAND` (аппаратный ГСЧ).
- TSC (счётчик времени).
- Другие источники, зависящие от конфигурации.
